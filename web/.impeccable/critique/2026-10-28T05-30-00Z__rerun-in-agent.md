# Re-run

The plugin's live-URL detector cannot settle on this dev server: its 30 s
navigation timeout never fires because the app holds a permanent WebSocket.
So the deterministic `detect` ran on source CSS, and the element-level rules
were re-implemented as a full-DOM walk in both themes; keyboard and viewport
checks reuse the Playwright harness.

## Evidence

- `impeccable detect web/src/styles.css` — clean: 0 anti-patterns, 0 advisories.
  (Radius steps 4px/10px are now documented scale steps in DESIGN.md; the 16px iOS
  zoom guard, 20px mobile total, 2px slider track and the Category-Stripe Rule are
  registered as reasoned ignore values in `.impeccable/config.json`.)
- Full-DOM audit, light and dark (effective composition of translucent backgrounds,
  `rgba()` and `color(srgb)`): 0 elements below 4.5:1, 0 text below 10px — after
  fixing the one regression the earlier AA round introduced: dark `sev--high` was
  white on the lifted `--bad` fill (2.99:1); now inked `#121316` via
  `--sev-high-ink` (6.22:1).
- kbtest keyboard suite: 19/19 (skip link, roving tabs, node focus/Enter/Escape,
  listbox, dialog trap + focus return, reduced motion).
- Mobile 390×844: opens at the 0.7 readable zoom centered on the priciest
  resource (NAT gateway ~$36.95 at x=195/390).
- Findings rows: strengths carry a quiet ✓ mark (21.6px wide, baseline-exact,
  5.3–5.7:1 in dark) instead of repeating the word "Strength" on every row.
